# Vendor note: where this skill's method comes from

This skill adapts the **method** of the open-source skill `sn-motion-html`, published in the repository `OpenSenseNova/SenseNova-Skills` under the MIT License. The upstream `LICENSE` file sits beside this note, unchanged. Credit for the core idea belongs to the upstream authors:

- one fixed, full-viewport media stage;
- a scroll-scrubbed route of stops and the clips between them;
- frame-matched seams at every join;
- two creative approval gates before any media is made in bulk;
- transparent copy laid over the picture, never baked into it;
- browser QA of the finished page.

## What this skill changed

| Upstream | Here | Why |
|---|---|---|
| Clips generated by a paid video API with a key in a project `.env` | No keys and no API. The human renders each passage by hand in Google Flow (Frames to Video: start frame = stop A, end frame = stop B) | Works for anyone with a Flow account; nothing secret lives in the project; no image ever leaves the machine except through the human's own upload |
| Two render rounds (scenes, then connectors cut from their boundary frames) | One round: every stop is painted first, so both ends of every passage are known before any render | Painted stops are pixel-exact; the end frame is the next stop |
| A plain HTML/JS runtime fetching clips as Blob URLs | An Astro component (`template/src/components/ScrollJourney.astro`) and a controller (`template/src/scripts/journey.ts`) that set `src` directly and rely on byte-range requests | Blob fetches need `blob:` in a site's Content Security Policy; range requests do not, and they stream |
| The upstream runtime's known gaps | Fixed in the controller: clip eviction, priming clips made after the first gesture, a truthful painted signal (`requestVideoFrameCallback`), time-based easing, place kept on resize and aspect flip, instant rail jumps, the fit test with a fonts-ready refit, reduced motion, Save-Data and a pause control | Each gap was hit on a real build |
| Post-render helpers (`verify_media.py`, `contact_sheet.py`, `make_posters.py`, `serve_project.py`) | A larger CPU toolkit under `scripts/`: boundary frames, seam check, colour match and paper lift, web normalise, seam repair, route sheet, media verify, loop seal, three hidden-cut and freeze detectors, a stop checker, placeholder stills and a browser battery | The seams have to be measured, not eyeballed; every tool carries a `--selftest` with a positive control |
| Story schema `story.json` and a passages manifest | A typed data file per journey (`template/src/data/journeys/*.ts`) plus the package's `STATUS.md` ledger | Typed data is checked at build time |

## What was not ported

- The upstream vanilla template (`assets/template/`), its style presets and its UI presets (folio, caption, graphic). The Astro component replaces the runtime; its look is set with CSS custom properties instead of presets.
- The upstream video-API pipeline script and its `.env` key handling. Never reintroduce them: this route has no keys by design.

## Security notes kept from a line-by-line review of the upstream code

- The upstream pipeline sent every still and prompt to a third-party video API as base64, and its retries each started a new paid task. Both are gone here.
- The upstream local preview server served the whole project folder. Here the site's own dev server serves only the site; the package folder (`ingredients/`, `renders/`, `work/`) never goes on a web host.

The toolkit scripts, the Astro template and every reference file in this skill are new work built on that method, released with this package.
