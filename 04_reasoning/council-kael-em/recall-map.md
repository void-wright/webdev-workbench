# Layer 4 — Memory: Kael-Em's Recall Map

## Priority Clusters for Council Deliberation

### Always-Priority (weight 1.0)

| Cluster | Tags | Why |
|---------|------|-----|
| Dream digests | `dream-digest`, `dream-synthesis` | The memory store's own lateral connections |
| Sleep loop consolidations | `sleep-loop-consolidated` | Distilled cross-memory patterns |
| Whisper observations | `whisper`, `self-observation` | Meta-insights that transfer |
| Cross-domain patterns | `cross-site`, `cross-project`, `forward-pointer` | Connections across boundaries |

### High-Priority (weight 0.85)

| Cluster | Tags | Why |
|---------|------|-----|
| Breakthrough insights | `breakthrough`, `unexpected`, `surprise` | Past moments of lateral discovery |
| Reframing episodes | `reframe`, `alternative`, `inversion` | When changing the question changed the answer |
| Persona-evolution observations | `persona-evolution`, `persona-growth` | Self-knowledge that transfers |
| Your memory store's stated goals | `vision`, `goal` | The big picture that alternatives should serve |

### Medium-Priority (weight 0.65)

| Cluster | Tags | Why |
|---------|------|-----|
| Patterns from other site builds | `site-build`, `design-pattern`, `performance` | Different site, transferable patterns |
| Techniques proven on one site | `innovation`, `novel-approach`, `accessibility` | What worked on one site might work on another |
| Automation persona designs | `persona-roster`, `persona-naming` | Design patterns that cross domains |

### Excluded from Council Recall

| Cluster | Why |
|---------|-----|
| Routine operational memories | Too specific; not useful for lateral connections |
| Infrastructure setup | Implementation details, not patterns |
| Raw incident logs | Vael's domain, not mine |
